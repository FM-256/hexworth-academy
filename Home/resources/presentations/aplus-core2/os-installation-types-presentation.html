Types of OS Installations Overview

Understanding the different installation methods available for deploying operating systems.

Clean Install

Fresh OS installation that formats the drive and replaces all existing data. Best for new hardware or major system problems.

Upgrade Install

Installs newer OS version over existing OS, preserving files, settings, and most applications. Faster than clean install.

Multiboot / Dual Boot

Multiple operating systems installed on separate partitions. Boot manager allows selection at startup.

Remote Network Installation

Boot from network adapter using PXE. Installation files hosted on server. Great for multiple computers.

Image Deployment

Capture configured system as image file and deploy to multiple computers. Fast, consistent deployments.

Repair Installation & Recovery

Reinstalls OS files or restores to previous state. Keeps user data. Fixes corrupted system files.

Speaker Notes: This overview provides a quick reference to all installation types. Each method serves specific use cases. Clean installs are most thorough but time-consuming. Upgrades balance speed with data preservation. Network and image deployments scale well for IT departments managing many machines.

Clean Install

Fresh OS Installation - The Nuclear Option

What is a Clean Install?

A clean install is a fresh operating system installation that formats the target drive and removes all existing data, resulting in a factory-fresh system.

Characteristics

  • Formats/replaces existing data - All files deleted
  • Creates new partitions - Fresh partition scheme
  • No legacy issues - No carried-over problems
  • Optimal performance - Cleanest system state
  • Time-consuming - Requires reinstalling everything

When to Use Clean Install

New Hardware
Fresh computer or new hard drive installation
Major System Issues
Severe corruption, malware infection, or instability
OS Architecture Change
Switching from 32-bit to 64-bit (upgrade not possible)
Repurposing Computer
Wiping system for new user or different purpose
CRITICAL WARNING: Clean install will delete ALL data on the target drive. Always backup important files to external storage before proceeding. Recovery is impossible after formatting!

Benefits vs Drawbacks

Benefits:
  • Factory-fresh performance
  • No legacy issues or conflicts
  • Clean partition scheme
  • Guaranteed clean system
Drawbacks:
  • Requires data backup/restore
  • Reinstall all applications
  • Reconfigure all settings
  • Time-consuming process
Speaker Notes: Clean install is the most thorough method but also the most disruptive. Emphasize the importance of backing up data first. It's the best choice when upgrading isn't possible (32-bit to 64-bit) or when the system has severe issues. Results in optimal performance but requires significant time investment to restore productivity.

Clean Install Process

Step-by-Step Installation Workflow

Clean Installation Steps

  1. Backup Data - Copy all important files to external storage or cloud backup
  2. Create Installation Media - USB drive or DVD with OS installation files
  3. Boot from Installation Media - Configure BIOS/UEFI to boot from USB/DVD first
  4. Delete Existing Partitions - Remove old partition structure (optional but recommended)
  5. Create New Partitions - Set up partition scheme (GPT for UEFI, MBR for Legacy)
  6. Format Partitions - Format with appropriate file system (NTFS for Windows)
  7. Install Operating System - Copy OS files and configure boot loader
  8. Initial Configuration - Language, region, user account, network settings
  9. Install Drivers - Hardware drivers for proper device functionality
  10. Windows Updates - Download and install latest security patches
  11. Install Applications - Reinstall needed software programs
  12. Restore User Data - Copy backed-up files back to system
Boot Order: During installation, you may need to access BIOS/UEFI firmware settings (usually F2, F12, Del, or Esc during startup) to change boot priority. Set USB or DVD drive as first boot device.
Typical Timeline:
  • OS Installation: 20-45 minutes
  • Driver Installation: 15-30 minutes
  • Windows Updates: 30-90 minutes
  • Application Reinstall: 1-3 hours
  • Data Restore: Varies by size
Exam Tip: Know that clean install requires booting from external media, formatting drives, and reinstalling everything. If a question mentions "preserving applications," clean install is NOT the answer.
Speaker Notes: Walk through the complete clean install process. Emphasize backup as step one - data loss is irreversible. Boot media creation and BIOS configuration are common troubleshooting areas. Deleting partitions is optional but recommended for truly clean installation. Post-install steps (drivers, updates, applications) often take longer than the OS installation itself.

Upgrade Install

In-Place OS Upgrade - Preserve Your Data

What is an Upgrade Install?

An upgrade install (in-place upgrade) installs a newer OS version over the existing OS while preserving files, settings, and most applications.

Characteristics

  • Preserves user files - Documents, photos, etc.
  • Keeps settings - User preferences maintained
  • Retains apps - Most applications remain installed
  • Faster than clean - No need to reinstall everything
  • May carry problems - Existing issues can persist

Requirements

Upgrade Prerequisites

  • Compatible source OS version
  • Same architecture (64-bit to 64-bit)
  • Same or higher edition tier
  • Sufficient disk space (20GB+ free)
  • Meet new OS hardware requirements

When to Use

  • Updating to newer Windows version
  • System is stable and working well
  • Want to preserve data and apps
  • Limited time for reinstallation

Benefits vs Drawbacks

Benefits:
  • Preserves files and settings
  • Most apps remain functional
  • Faster than clean install
  • Less manual reconfiguration
Drawbacks:
  • May carry over existing problems
  • Some apps may be incompatible
  • Not possible for all OS transitions
  • Requires compatible source OS
Exam Tip: Upgrade install preserves data (usually). Clean install does NOT. If scenario requires keeping user files and applications, recommend upgrade. If 32-bit to 64-bit, upgrade is impossible - must use clean install.
Speaker Notes: Upgrade install is the middle ground between clean install and doing nothing. It preserves user data while updating the OS. Emphasize compatibility requirements - not all OS versions can upgrade to all other versions. 32-bit cannot upgrade to 64-bit. Some editions cannot upgrade to lower editions. Always backup before upgrading as a safety measure.

Upgrade Compatibility

Understanding Upgrade Paths and Requirements

Valid Windows Upgrade Paths

To Windows 10

  • Windows 7 (SP1) → Windows 10
  • Windows 8.1 → Windows 10
  • Windows 10 → Windows 10 (feature update)

To Windows 11

  • Windows 10 (20H1 or later) → Windows 11
  • Must meet Windows 11 hardware requirements
  • Windows 7/8.1 → Windows 11 requires clean install

Windows 11 Requirements

Hardware Requirements

  • TPM 2.0 - Trusted Platform Module 2.0
  • Secure Boot - UEFI firmware with Secure Boot capable
  • 64-bit CPU - 1 GHz or faster, 2+ cores, compatible processor
  • 4 GB RAM minimum (8 GB recommended)
  • 64 GB storage minimum
  • UEFI firmware - No Legacy BIOS support
  • DirectX 12 compatible graphics

Edition Upgrade Rules

Edition Compatibility:
  • Home → Home (valid)
  • Pro → Pro (valid)
  • Home → Pro (valid with license upgrade)
  • Pro → Home (NOT VALID - requires clean)
Architecture Limitation:
32-bit Windows CANNOT upgrade to 64-bit Windows. Must perform clean install to change architecture.
Use PC Health Check Tool:
Microsoft provides PC Health Check app to verify Windows 11 compatibility before attempting upgrade.
Exam Tip: Memorize Windows 11 requirements: TPM 2.0, Secure Boot, UEFI, 64-bit CPU. If scenario mentions "old BIOS system" or "no TPM chip," Windows 11 upgrade is not possible without hardware changes. 32-bit to 64-bit always requires clean install.
Speaker Notes: Windows 11 introduced strict hardware requirements that block many older computers from upgrading. TPM 2.0 and Secure Boot are the most common blockers. Edition rules matter - you can't downgrade editions via upgrade path. Architecture is fixed during upgrade - changing from 32-bit to 64-bit requires clean install. Always run compatibility checker before attempting upgrade.

In-Place Upgrade vs Feature Update

Understanding Different Types of Windows Updates

In-Place Upgrade

Definition: Major version change from one OS version to another (e.g., Windows 10 → Windows 11)

Characteristics:

  • Major OS version change
  • Windows 7/8.1 → Windows 10
  • Windows 10 → Windows 11
  • Requires installation media or upgrade assistant
  • Preserves files, settings, apps
  • May require license upgrade
  • Takes 30-90 minutes typically

Feature Update

Definition: Semi-annual update within same Windows version (e.g., Windows 10 21H2 → 22H2)

Characteristics:

  • Same OS, new features
  • Windows 10: 21H2 → 22H2 → etc.
  • Windows 11: 22H2 → 23H2 → etc.
  • Delivered via Windows Update
  • Preserves all data and settings
  • No license change needed
  • Takes 20-45 minutes typically

Both Methods Preserve Data

Both in-place upgrades and feature updates preserve user files, applications, and settings. The difference is scope: in-place upgrades change OS version entirely, while feature updates add new features to existing OS version.

Aspect In-Place Upgrade Feature Update
OS Version Changes major version (Win 10 → 11) Same version (Win 10 21H2 → 22H2)
Delivery Method Installation media / Upgrade Assistant Windows Update
Frequency Occasional (every few years) Regular (twice yearly for Win 10)
License May require new license Same license
Data Preservation Yes (files, settings, apps) Yes (files, settings, apps)
Time Required 30-90 minutes 20-45 minutes
Exam Tip: Both in-place upgrade and feature update preserve data. The key difference is scope: in-place changes OS version, feature update adds features to current version. Feature updates come through Windows Update automatically.
Speaker Notes: Clarify the distinction between these terms. In-place upgrade is major OS version change (10 to 11). Feature update is within-version update (Windows 10 21H2 to 22H2). Both preserve data, but in-place upgrades may require new license and have stricter hardware requirements. Feature updates are routine maintenance delivered via Windows Update.

Multiboot / Dual Boot

Multiple Operating Systems on One Computer

What is Multiboot?

A multiboot or dual boot configuration allows multiple operating systems to be installed on a single computer, each on its own partition. A boot manager lets you choose which OS to load at startup.

Key Concepts

  • Separate Partitions - Each OS on dedicated partition
  • Boot Manager - Menu to select OS at startup
  • One OS at a Time - Cannot run simultaneously (unlike VMs)
  • Shared Hardware - All OS share same physical resources
  • Requires Reboot - Must restart to switch OS

Common Use Cases

Testing & Development
Test software on different OS versions without separate hardware
Compatibility
Run legacy applications requiring older OS
Linux & Windows
Dual boot Windows for games, Linux for development
Work & Personal
Separate OS for work vs personal use

Considerations for Multiboot

  • Disk Space - Each OS requires 20-50GB minimum, plus space for applications and files
  • Boot Order - Boot manager configuration determines default OS and timeout
  • File System Compatibility - Windows uses NTFS, Linux uses ext4 (cross-access may be limited)
  • Partition Scheme - GPT recommended for UEFI systems, supports more partitions than MBR
  • Maintenance - Each OS needs separate updates, patches, and antivirus
Important: Install older operating systems first, then newer ones. Newer OS boot managers are usually backward-compatible and will detect older OS installations. Installing older OS last may overwrite newer boot manager.
Speaker Notes: Multiboot allows multiple OS on one computer via separate partitions. Unlike virtual machines, only one OS runs at a time - requires reboot to switch. Common for developers and enthusiasts. Key considerations: sufficient disk space (each OS needs 20-50GB+), partition planning, and boot manager configuration. Install older OS first to avoid boot manager conflicts.

Setting Up Dual Boot

Step-by-Step Dual Boot Configuration

Dual Boot Installation Process

  1. Backup All Data - Partitioning carries risk of data loss
  2. Install First OS - Usually the older OS (e.g., Windows 10 before Windows 11)
  3. Shrink Existing Partition - Free up space for second OS
    • Windows: Disk Management → Shrink Volume
    • Allocate 50-100GB for second OS
  4. Create New Partition - Use unallocated space for second OS
  5. Install Second OS - Boot from installation media, select new partition
    • Installer should detect first OS automatically
    • Do NOT format existing OS partition
  6. Boot Manager Auto-Configures - Modern installers create boot menu automatically
  7. Configure Boot Options - Set default OS and timeout (optional)

Windows Boot Manager

# View boot configuration (Windows) bcdedit # Set default OS by identifier bcdedit /default {identifier} # Set boot menu timeout (seconds) bcdedit /timeout 30 # Rename OS display name bcdedit /set {identifier} description "Windows 11 Pro"

Common Issues

Boot Menu Missing
If second OS doesn't appear, use bcdedit or EasyBCD to rebuild boot configuration.
Wrong OS Boots Default
Change default OS with: bcdedit /default {id}
Partition Not Visible
Ensure partition is marked as "active" or has correct flags set.
Exam Tip: For dual boot setup: shrink existing partition to create space, install second OS to new partition, boot manager auto-configures. Use bcdedit command to manage Windows boot configuration. Install older OS first to avoid boot manager conflicts.
Speaker Notes: Dual boot setup requires careful partition management. Shrinking partitions carries some risk, so backup first. Modern OS installers automatically detect existing OS and configure boot manager. bcdedit is the command-line tool for managing Windows boot configuration. Third-party tools like EasyBCD provide GUI for boot management. Always install older OS first - newer boot managers detect older OS better than vice versa.

Network / Remote Installation

PXE Boot and Windows Deployment Services

PXE (Preboot Execution Environment)

PXE allows computers to boot from network adapter instead of local storage, loading OS installation files from a server.

How PXE Works

  1. Computer powers on, network card initializes
  2. PXE ROM sends DHCP request
  3. DHCP server responds with IP and boot server address
  4. Client downloads boot image via TFTP
  5. Boot image loads installation environment
  6. OS installation proceeds from network share

Windows Deployment Services (WDS)

WDS is Microsoft's server role that provides PXE-based network installation of Windows operating systems.

WDS Components

  • PXE Server - Responds to client boot requests
  • TFTP Server - Transfers boot files
  • Boot Images - Windows PE environment
  • Install Images - Full OS installation files
  • Multicast Support - Deploy to many PCs simultaneously

Benefits of Network Installation

  • Centralized Management - All installation files on server, easy updates
  • No Physical Media - No need to create/distribute USB drives or DVDs
  • Multiple Simultaneous Installs - Deploy to many computers at once
  • Consistent Deployments - Same image for all computers
  • Remote Locations - Install OS on computers anywhere on network

PXE Requirements

  • Network adapter with PXE support (most modern NICs)
  • PXE boot enabled in BIOS/UEFI
  • DHCP server on network
  • WDS server (or other PXE server) hosting installation files
  • Network connectivity to server during installation
Exam Tip: PXE = network boot. If scenario mentions "installing OS on multiple computers without physical media" or "network-based installation," the answer is PXE/WDS. Requires network adapter support and server infrastructure.
Speaker Notes: PXE network installation is ideal for IT departments managing many computers. Client boots from network adapter (no local media needed), downloads installation files from server. WDS is Microsoft's implementation for Windows deployments. Multicast feature allows deploying to hundreds of computers simultaneously. Requires infrastructure: DHCP server, WDS server, network connectivity. Enable PXE in BIOS and set network boot priority.

Image-Based Deployment

Capture, Customize, and Deploy System Images

What is Image Deployment?

Image deployment captures a fully configured computer as a system image file, then deploys that image to multiple computers for fast, consistent installations.

Image Deployment Process

  1. Build Reference Computer - Install and configure OS, drivers, apps
  2. Generalize with Sysprep - Remove unique identifiers (SID, computer name)
  3. Capture Image - Create WIM or VHD file of entire system
  4. Store on Server - Place image on network share or WDS server
  5. Deploy to Targets - Apply image to destination computers
  6. Specialize on Boot - Generate new SID, computer name, join domain

Tools for Image Deployment

DISM (Deployment Image Servicing)

Command-line tool for capturing and applying Windows images (.wim files)

MDT (Microsoft Deployment Toolkit)

Free deployment solution with GUI for managing images and deployments

SCCM (System Center Configuration Manager)

Enterprise deployment and management platform (now called Microsoft Endpoint Manager)

Sysprep

System Preparation tool to generalize Windows before imaging

# Generalize system with Sysprep (before capture) C:\Windows\System32\Sysprep\sysprep.exe /generalize /oobe /shutdown # Capture image with DISM (from Windows PE) DISM /Capture-Image /ImageFile:C:\install.wim /CaptureDir:D:\ /Name:"Windows 10 Corporate" # Apply image to drive with DISM DISM /Apply-Image /ImageFile:C:\install.wim /Index:1 /ApplyDir:C:\
Critical: Always run Sysprep before capturing an image. Sysprep removes unique system identifiers (SID, computer name, etc.). Deploying non-generalized images causes duplicate SIDs and network conflicts.
Speaker Notes: Image deployment is the standard for enterprise OS deployment. Build one reference computer with all needed software, run Sysprep to generalize it, capture as image, deploy to many computers. Sysprep is critical - it removes unique identifiers so each deployed computer gets new SID/name. DISM is built into Windows for capture/apply. MDT adds GUI and automation. SCCM is full enterprise solution. Much faster than individual installations.

Repair Installation

Fix System Files Without Losing Data

What is Repair Installation?

A repair installation reinstalls Windows system files without deleting user data, settings, or applications. It fixes corrupted OS files while preserving personal files.

Types of Repair

In-Place Upgrade Repair
Run Windows installer over existing installation. Keeps everything.
Reset This PC (Keep Files)
Reinstalls Windows but keeps personal files. Removes apps.
SFC / DISM Repair
Command-line tools to repair system files in-place.

When to Use Repair

  • Corrupted System Files - Missing or damaged OS files
  • Boot Problems - Windows won't start properly
  • Feature Malfunctions - Core Windows features broken
  • After Malware Removal - Restore system integrity
  • Update Failures - Fixing failed update installations

Benefits

  • Keeps user files (documents, photos, etc.)
  • Faster than clean install
  • No need to reinstall everything
  • Fixes most system file corruption
  • Less disruptive than clean install
# System File Checker - scans and repairs system files sfc /scannow # DISM - repair Windows image source files DISM /Online /Cleanup-Image /RestoreHealth # Recommended: Run DISM first, then SFC DISM /Online /Cleanup-Image /RestoreHealth && sfc /scannow

Reset This PC (Keep My Files)

Windows 10/11 includes "Reset this PC" feature:

  • Settings → System → Recovery → Reset this PC
  • Choose "Keep my files" option
  • Reinstalls Windows while preserving personal files
  • Removes installed applications (built-in apps remain)
  • Resets settings to defaults
Exam Tip: Repair installation keeps user data. Clean install does NOT. If scenario says "fix system issues without losing files," recommend repair installation or Reset PC (Keep files). SFC and DISM are first-line repair tools.
Speaker Notes: Repair installation fixes system problems while preserving user data. Three main methods: in-place upgrade repair (reinstall same Windows version), Reset PC with "Keep files," or SFC/DISM commands. SFC scans and repairs system files. DISM repairs the Windows image that SFC uses as reference. Always run DISM before SFC for best results. Reset PC is user-friendly but removes applications. In-place repair keeps everything.

Recovery Options

Windows Recovery Environment and Restore Methods

Reset This PC

Keep my files: Reinstalls Windows, keeps personal files, removes apps

Remove everything: Equivalent to clean install

System Restore

Reverts system files and settings to previous restore point. Does not affect personal files. Reverses recent changes.

System Image Recovery

Restores entire system from full backup image created earlier. Returns computer to exact state when image was created.

Recovery Drive

Bootable USB drive containing Windows Recovery Environment. Used to troubleshoot when Windows won't boot.

Startup Repair

Automatically fixes common boot problems like corrupted BCD, missing boot files, or boot sector issues.

Command Prompt (WinRE)

Access command line from recovery to run DISM, SFC, bootrec, diskpart, and other repair commands.

Windows Recovery Environment (WinRE)

WinRE is a minimal OS environment for troubleshooting and recovery when Windows won't boot normally.

Ways to Access WinRE:

  • Settings → Update & Security → Recovery → Restart now (Advanced startup)
  • Shift + Restart from Start menu power options
  • Boot from installation media → Repair your computer
  • Three failed boot attempts triggers automatic WinRE
  • Boot from Recovery Drive USB created earlier
Creating Recovery Drive:
  1. Search "Recovery Drive" in Windows
  2. Connect USB drive (16GB+ recommended)
  3. Check "Back up system files"
  4. Follow wizard to create bootable USB
Exam Tip: System Restore = revert to restore point. System Image Recovery = restore full backup. Reset PC = reinstall Windows. Recovery Drive = bootable troubleshooting USB. Know the differences!
Speaker Notes: Windows provides multiple recovery options. Reset PC reinstalls Windows (optionally keeping files). System Restore rolls back to restore point without affecting personal files. System Image Recovery restores entire drive from backup. WinRE is recovery environment for troubleshooting boot issues. Recovery Drive is bootable USB with WinRE. Access WinRE via Settings, Shift+Restart, installation media, or automatic trigger after failed boots.

Boot Media Types

Installation Media Options and Use Cases

USB Flash Drive

Most Common: Fast, reusable, widely supported. Minimum 8GB for Windows. Easy to create with Media Creation Tool or Rufus.

DVD / Blu-ray Disc

Traditional: Slower than USB but universal. DVD (4.7GB) sufficient for Windows. Read-only ensures integrity. Becoming less common.

Network (PXE)

Enterprise: Boot from network adapter. No physical media needed. Ideal for multiple deployments. Requires PXE server infrastructure.

SD Card

Portable Devices: Common for tablets and small form-factor PCs. Works like USB drive but may be slower depending on card class.

External Hard Drive

Large Capacity: Useful when storing multiple OS images. Can hold various tools and drivers. Faster than optical media.

ISO File (Virtual)

Virtual Machines: Mount ISO directly in VM software. Also used to burn to physical media. Download format from Microsoft.

Media Type Speed Reusable Typical Size Best Use Case
USB Flash Drive Fast (USB 3.0+) Yes 8-32 GB General purpose, field technician
DVD/Blu-ray Slow No (writeable: once) 4.7 GB / 25 GB Archival, older systems
Network (PXE) Fast (gigabit) N/A N/A Multiple deployments, enterprise
SD Card Moderate Yes 8-128 GB Tablets, small devices
External HDD Fast Yes 500 GB+ Multiple images, technician toolkit
Exam Tip: USB flash drive is most common for modern installations - fast, reusable, widely supported. PXE/network boot is for enterprise environments with multiple computers. DVD is legacy but still valid. ISO is download format that must be written to physical media or mounted in VM.
Speaker Notes: USB flash drives have replaced optical media as primary installation medium - they're faster, reusable, and easier to create. Minimum 8GB for Windows installation. Network PXE boot eliminates physical media entirely but requires infrastructure. DVDs still work but are slow and single-use. External drives can hold multiple OS images and tools. ISO files are downloaded then burned to media or mounted in VMs.

Creating Installation Media

Tools and Methods for Bootable USB Creation

Media Creation Tool (Official)

Microsoft's official tool for creating Windows 10/11 installation media.

Using Media Creation Tool:

  1. Download from Microsoft website
  2. Run MediaCreationTool.exe
  3. Accept license terms
  4. Choose "Create installation media"
  5. Select language, edition, architecture
  6. Choose USB flash drive or ISO file
  7. Select target USB drive (8GB+)
  8. Tool downloads Windows and creates bootable USB
Advantages: Official Microsoft tool, downloads latest Windows version, automatic process, includes license compliance.

Rufus (Third-Party)

Popular third-party tool for creating bootable USB drives from ISO files.

Using Rufus:

  1. Download Rufus from rufus.ie
  2. Download Windows ISO separately
  3. Insert USB drive (8GB+)
  4. Launch Rufus
  5. Select USB device
  6. Click SELECT and choose ISO file
  7. Set partition scheme:
    • GPT for UEFI systems
    • MBR for Legacy BIOS
  8. Click START to create bootable USB
Advantages: Fast, flexible, supports multiple partition schemes, works with various OS (Windows, Linux), advanced options.

Bootable USB Requirements

  • Minimum 8 GB USB drive (16 GB recommended for Windows 11)
  • USB drive will be formatted - backup any existing data first!
  • USB 3.0 recommended - significantly faster than USB 2.0
  • Match partition scheme to firmware: GPT for UEFI, MBR for Legacy BIOS
Important: Creating bootable media ERASES all data on the USB drive. Back up any files before proceeding. USB drive must be at least 8GB for Windows installation.
Exam Tip: Media Creation Tool is official Microsoft method. Rufus is third-party alternative with more options. Both create bootable USB. GPT partition scheme for UEFI systems, MBR for Legacy BIOS. Minimum 8GB USB drive required.
Speaker Notes: Two main methods: Microsoft's Media Creation Tool (easiest, official) and Rufus (more control, third-party). Media Creation Tool downloads Windows automatically and creates USB in one process. Rufus requires separate ISO download but offers more options like partition scheme selection. Always backup USB drive first - creation process formats it. Match partition scheme to firmware: GPT for UEFI, MBR for Legacy BIOS.

Partitioning Basics

MBR vs GPT and Partition Types

MBR (Master Boot Record)

Legacy Partitioning Scheme
Used with Legacy BIOS systems

MBR Characteristics:

  • Maximum 4 primary partitions (or 3 primary + 1 extended)
  • Extended partition can contain unlimited logical drives
  • 2 TB maximum disk size per partition
  • 32-bit partition table
  • Legacy BIOS compatibility
  • Boot sector at beginning of disk

Partition Types in MBR:

  • Primary - Bootable, max 4 total
  • Extended - Container for logical drives
  • Logical - Partitions within extended partition

GPT (GUID Partition Table)

Modern Partitioning Scheme
Required for UEFI systems and Windows 11

GPT Characteristics:

  • Up to 128 partitions on Windows (no primary/extended distinction)
  • 9.4 ZB maximum disk size (essentially unlimited)
  • 64-bit partition table
  • UEFI firmware required (but can work with BIOS in CSM mode)
  • Redundant partition table for reliability
  • CRC error detection for data integrity

Special GPT Partitions:

  • EFI System Partition (ESP) - Stores boot loaders (FAT32, 100-500MB)
  • MSR (Microsoft Reserved) - Reserved space (16-128MB)
  • Recovery Partition - Windows Recovery Environment
Feature MBR GPT
Maximum Partitions 4 primary (or 3 + extended) 128 partitions
Maximum Disk Size 2 TB 9.4 ZB (essentially unlimited)
Firmware Compatibility Legacy BIOS UEFI (required for Windows 11)
Data Protection Single partition table Redundant table + CRC checks
Windows 11 Support No Yes (required)
Exam Tip: GPT required for UEFI systems and Windows 11. MBR for Legacy BIOS. MBR limited to 4 primary partitions and 2TB disks. GPT supports 128 partitions and huge disks. Remember: MBR = 4 partitions max, 2TB max. GPT = 128 partitions, 9.4ZB max.
Speaker Notes: MBR is legacy scheme with 4 partition limit and 2TB disk limit. GPT is modern standard required for UEFI and Windows 11, supporting 128 partitions and massive disks. GPT includes redundancy and error checking MBR lacks. Windows 11 requires GPT. If converting between schemes, backup data first - conversion typically requires reformatting. Use diskpart or Disk Management to view/modify partitions.

File Systems

Understanding Different File System Types

NTFS (New Technology File System)

Windows Standard: Default for Windows. Supports large files, permissions, encryption, compression. Maximum file size: 16 EB. Best for Windows installations.

FAT32 (File Allocation Table 32)

Legacy Compatibility: Universal compatibility across OS. 4 GB max file size. 32 GB max partition (Windows). Good for USB drives, older devices.

exFAT (Extended FAT)

Removable Media: Designed for flash drives. No 4GB file limit. Cross-platform compatible. Ideal for large files on external drives (videos, backups).

ext4 (Fourth Extended File System)

Linux Standard: Default Linux file system. Journaling for reliability. Not natively supported by Windows. Maximum file size: 16 TB. Excellent performance.

APFS (Apple File System)

macOS Standard: Modern macOS/iOS file system. Optimized for SSDs. Encryption, snapshots, space sharing. Not accessible from Windows without third-party tools.

ReFS (Resilient File System)

Windows Server: Enhanced reliability for servers and workstations. Built-in resilience. Available in Pro for Workstations and Server editions only.

Choosing the Right File System

  • Windows installation: NTFS (only option for modern Windows)
  • Cross-platform USB drive (small files): FAT32
  • Large files on external drive: exFAT
  • Linux installation: ext4 (or btrfs, xfs)
  • macOS installation: APFS
Exam Tip: NTFS is Windows standard (supports large files, security, encryption). FAT32 has 4GB file size limit (common issue with large videos). exFAT for removable media with large files. ext4 for Linux. APFS for macOS. Know file size limitations!
Speaker Notes: File systems determine how data is stored on disk. NTFS is Windows standard with full feature support. FAT32 is legacy with 4GB file size limit but universal compatibility - common issue when copying large files. exFAT solves FAT32 file size problem for removable media. ext4 is Linux default. APFS is modern macOS. Windows installations must use NTFS. USB drives often use FAT32 or exFAT depending on file sizes.

An unattended installation uses an answer file to automatically provide responses to installation prompts, allowing OS deployment without user interaction.

  • Mass deployment efficiency

  • Reduced human error

  • Network settings
  • Domain join credentials
  • Time zone
Post-Installation:
  • Install drivers
  • Install applications
  • Configure Windows settings
