What is a Workgroup?

Peer-to-Peer Network Model

Workgroup Definition

A workgroup is a peer-to-peer network model where each computer manages its own security, user accounts, and resources independently. No central server is required.

Key Characteristics

  • Peer-to-Peer Model - All computers are equal
  • Decentralized Management - Each PC is independent
  • Local User Accounts - Stored on each individual computer
  • No Central Server - No domain controller required
  • Simple File Sharing - Share folders and printers locally
  • Small Scale - Recommended maximum of ~20 computers

Visual Representation

Local Accounts
PC 2
Local Accounts
↕
PC 3
Local Accounts
PC 4
Local Accounts

Each computer manages its own users and resources

Important: In a workgroup, if a user needs access to resources on multiple computers, they must have a separate user account created on EACH computer. There is no account synchronization.
Speaker Notes: Emphasize that workgroups are peer-to-peer - no computer has authority over others. This is fundamentally different from domains. The 20-computer limitation is not a technical hard limit, but a practical guideline. Managing more than 20 computers in a workgroup becomes administratively burdensome because you must configure each computer individually.

Workgroup Characteristics

How Workgroups Operate

🔓 Decentralized Management

Each computer administrator manages their own computer independently. No centralized control or policies.

👤 Local User Accounts

User accounts exist only on individual computers. Must create separate accounts on each PC users need to access.

📁 Simple File/Printer Sharing

Share folders and printers using simple sharing settings. Access controlled by local permissions.

❌ No Single Sign-On

Users must authenticate separately to each computer. No unified login credentials across the network.

💰 Zero Additional Cost

No server licenses or additional software required. Uses built-in Windows features only.

⚙️ Individual Configuration

Security policies, updates, and settings must be configured on each computer separately.

Administrative Challenge: In a 10-computer workgroup, creating a new user requires creating 10 separate accounts (one on each computer). Changing a password requires updating it on all 10 computers manually. This doesn't scale well!
Example Scenario: A small dental office with 5 computers. The dentist, office manager, and 2 assistants each need access to the scheduling computer and their own workstation. A workgroup is appropriate here - simple setup, minimal IT knowledge required, and the small number of computers makes manual management feasible.
Speaker Notes: The key limitation of workgroups is administrative overhead. While technically you could have more than 20 computers in a workgroup, the management burden becomes impractical. Each computer must be configured individually, accounts must be created multiple times, and there's no way to enforce consistent security policies across all computers.

What is a Domain?

Client-Server Network Model

Domain Definition

A domain is a client-server network model where a central server (Domain Controller) manages authentication, user accounts, and security policies for all computers and users in the network.

Key Characteristics

  • Client-Server Model - Central authority structure
  • Centralized Management - Managed from Domain Controller
  • Active Directory - Directory service storing all accounts
  • Domain Controller (DC) - Server providing authentication
  • Single Sign-On - One account works on all domain computers
  • Enterprise Scale - Supports thousands of computers

Visual Representation

Domain Controller
Active Directory
Central Authentication
↓
Client PC 1
Client PC 2
Client PC 3

All computers authenticate against the central Domain Controller

Important: In a domain, user accounts are created ONCE in Active Directory and work on ALL domain-joined computers. Users can log in to any domain computer with the same credentials.
Speaker Notes: Domains represent a fundamental shift from peer-to-peer to client-server architecture. The Domain Controller is the central authority that all other computers trust for authentication decisions. Active Directory is the database that stores all user accounts, computer accounts, groups, and organizational structure. This centralized model enables single sign-on - create a user once, they can access any domain resource.

Domain Characteristics

How Domains Operate

🔐 Centralized Authentication

Domain Controller validates all user logins. Single source of truth for user credentials across the entire network.

📋 Group Policy Management

Administrators can enforce security settings, configurations, and restrictions across all domain computers from one location.

🎫 Single Sign-On (SSO)

Users log in once with domain credentials and gain access to all authorized network resources without re-authenticating.

📈 Scalable Architecture

Supports thousands of computers and users. Enterprise organizations commonly have 10,000+ domain-joined devices.

🔄 Automatic Replication

Multiple Domain Controllers can replicate Active Directory data for redundancy and distributed authentication.

🛡️ Enhanced Security

Kerberos authentication protocol, password policies, account lockout, audit logging, and fine-grained security controls.

Administrative Efficiency: In a 1,000-computer domain, creating a new user requires ONE action in Active Directory. That user can immediately log in to any of the 1,000 domain computers. Password changes take effect instantly across the entire network.
Example Scenario: A corporate office with 200 employees and 250 computers. Users move between conference rooms, hot-desk in different areas, and need access to shared network drives and printers. A domain is essential here - centralized account management, consistent security policies, and single sign-on across all resources.
Speaker Notes: Domains excel at scale and centralized control. Group Policy alone is a game-changer - deploy software, enforce security settings, configure desktop environments, all from a central management console. Kerberos provides mutual authentication and is more secure than the NTLM used in workgroups. The trade-off is complexity and cost - you need Windows Server licenses and IT expertise to maintain the infrastructure.

Active Directory Overview

Microsoft's Directory Service

What is Active Directory?

Active Directory (AD) is Microsoft's directory service that stores information about network objects (users, computers, groups, printers) in a hierarchical database and makes this information available for authentication and resource access.

Active Directory Components

  • Objects - Users, computers, groups, OUs, printers
  • Schema - Defines what types of objects can exist
  • Domain - Administrative boundary and namespace
  • Tree - Collection of domains in a hierarchy
  • Forest - Collection of trees (highest level)
  • Organizational Units (OUs) - Containers for organizing objects
  • LDAP - Lightweight Directory Access Protocol (query protocol)

Hierarchical Structure

  1. Forest (Top Level)
    Example: Company.com forest
  2. Domain (Within Forest)
    Example: Sales.Company.com, IT.Company.com
  3. Organizational Units (OUs)
    Example: Marketing OU, HR OU, Engineering OU
  4. Objects (Bottom Level)
    Example: User accounts, computer accounts, groups
Example Active Directory Path:
CN=John Smith,OU=Marketing,OU=Employees,DC=company,DC=local
Translation: User "John Smith" in the Marketing OU, which is inside the Employees OU, in the company.local domain
Exam Tip: Active Directory uses LDAP (Lightweight Directory Access Protocol) for queries. LDAP runs on port 389 (unencrypted) or port 636 (LDAPS - encrypted). Know that AD is the Microsoft implementation of directory services.
Speaker Notes: Active Directory is the foundation of Windows domain networking. The hierarchical structure (Forest > Domain > OU > Objects) allows for organized management and delegation of administrative tasks. OUs are containers used to organize objects and apply Group Policies. The forest is the security boundary - all domains within a forest trust each other by default. LDAP is the query protocol used to search and modify AD objects.

Domain Controller (DC)

The Heart of Active Directory Domains

What is a Domain Controller?

A Domain Controller (DC) is a Windows Server running the Active Directory Domain Services (AD DS) role. It authenticates users and computers, stores the Active Directory database, and enforces security policies.

Domain Controller Functions

  • Authentication - Validates user and computer logons using Kerberos
  • Authorization - Determines what resources users can access
  • Directory Storage - Hosts the Active Directory database (NTDS.dit)
  • Replication - Synchronizes AD data with other DCs in the domain
  • Group Policy Processing - Provides policies to client computers
  • DNS Integration - Usually also runs DNS server for domain resolution

FSMO Roles

Flexible Single Master Operations (FSMO) are specialized roles assigned to Domain Controllers:

Forest-Wide Roles (1 per Forest):
  • Schema Master - Controls schema modifications
  • Domain Naming Master - Controls adding/removing domains
Domain-Wide Roles (1 per Domain):
  • PDC Emulator - Primary DC, password changes, time sync
  • RID Master - Allocates unique IDs for new objects
  • Infrastructure Master - Updates cross-domain references
Best Practice: Always have at least TWO Domain Controllers for redundancy. If the only DC fails, no one can log in and the entire domain becomes inaccessible. Multiple DCs provide fault tolerance and load balancing.
Exam Tip: Know that Domain Controllers require Windows Server (not Windows 10/11). The PDC Emulator is the most important FSMO role - it handles password changes and acts as the authoritative time source.
Speaker Notes: Domain Controllers are critical infrastructure - they're the authentication gatekeepers. The NTDS.dit file contains the entire AD database. FSMO roles are unique responsibilities that can only be performed by one DC at a time (to prevent conflicts). The PDC Emulator gets priority for password changes - when you change your password, it's immediately replicated to the PDC Emulator so you can log in with it right away.

Authentication: Workgroup Model

Local Authentication Process

How Workgroup Authentication Works

In a workgroup, each computer maintains its own Security Accounts Manager (SAM) database containing local user accounts. Authentication is performed locally against this database.

Authentication Process

  1. User enters credentials (username/password) at login screen
  2. Local Security Authority (LSA) receives the credentials
  3. SAM database is queried for matching username
  4. Password hash is compared against stored hash
  5. Access token is created if authentication succeeds
  6. User logs in to the local computer only

Key Limitations

  • No password synchronization between computers
  • Each computer has independent user accounts
  • Passwords can differ on each computer
  • No centralized password policy enforcement

Authentication Diagram

JohnDoe / Password123
↓
Local Computer
SAM Database
Local Accounts Only
↓
✓ Authentication Success
Access to THIS computer only
Problem Scenario: John needs access to 5 computers in a workgroup. The administrator must create the "John" account 5 separate times (once on each computer). If John changes his password, he must remember to change it on all 5 computers or passwords become out of sync.

C:\Windows\System32\config\SAM
Speaker Notes: The SAM database is encrypted and cannot be directly accessed while Windows is running. Each Windows computer has its own SAM with local accounts. Workgroup authentication uses NTLM (NT LAN Manager) protocol. The lack of centralized account management is the biggest weakness of workgroups - it's administratively intensive and error-prone at scale.

Authentication: Domain Model

Centralized Kerberos Authentication

How Domain Authentication Works

In a domain, user credentials are stored in Active Directory on the Domain Controller. Authentication uses the Kerberos protocol, which provides secure, ticket-based authentication with mutual verification.

Kerberos Authentication Process

  1. User enters domain credentials (DOMAIN\username or user@domain.com)
  2. Client contacts Domain Controller to request Ticket Granting Ticket (TGT)
  3. DC verifies credentials against Active Directory database
  4. TGT is issued and cached on client (valid for 10 hours default)
  5. Client uses TGT to request service tickets for resources
  6. Single sign-on achieved - No re-authentication needed for domain resources

Key Advantages

  • Mutual authentication (client and server verify each other)
  • Passwords never sent over the network
  • Ticket-based system prevents replay attacks
  • Single sign-on to all domain resources

Authentication Diagram

User Login
COMPANY\JohnDoe
↓
Domain Controller
Active Directory
Kerberos (Port 88)
↓
✓ TGT Issued
Access to ALL domain resources

Credentials stored centrally - work on any domain computer

Benefit Scenario: John logs in to ANY domain-joined computer with his domain credentials. Active Directory authenticates him, issues a TGT, and now he can access file servers, printers, email, and any other domain resource without re-entering credentials. One account, unlimited access.
# View cached Kerberos tickets on client
klist

# Purge Kerberos tickets (force re-authentication)
klist purge

# View domain user info
net user JohnDoe /domain
Exam Tip: Kerberos uses port 88 (TCP/UDP). Default TGT lifetime is 10 hours, max renewal is 7 days. If a scenario mentions centralized authentication, ticket-based authentication, or Single Sign-On, the answer involves domain/Kerberos.
Speaker Notes: Kerberos is significantly more secure than NTLM. The TGT (Ticket Granting Ticket) acts as proof of authentication - clients present it to request service tickets for specific resources. Passwords are never sent over the network - only hashed credentials. The Domain Controller is called the Key Distribution Center (KDC) in Kerberos terminology. Time synchronization is critical - if client and DC clocks differ by more than 5 minutes, authentication fails.

Joining a Workgroup

How to Configure Workgroup Membership

Workgroup Configuration

Joining a workgroup is simple and requires no server infrastructure. All Windows editions (Home, Pro, Enterprise) can join workgroups.

Steps to Join a Workgroup

  1. Open System Properties
    Right-click This PC → Properties
  2. Click "Change settings" next to Computer name
  3. Click "Change" button in System Properties dialog
  4. Select "Workgroup" radio button
  5. Enter workgroup name (e.g., "WORKGROUP", "OFFICE")
  6. Click OK and restart the computer
  7. Computer is now in the workgroup

Important Notes

Workgroup Names:
  • Default workgroup name is "WORKGROUP"
  • Case-insensitive (WORKGROUP = workgroup)
  • All computers must use the SAME workgroup name to see each other in Network
  • No server validation - just a label
Requirements:
  • Local administrator access required
  • Restart required after change
  • No server needed
  • Works on all Windows editions
# Join workgroup via command line (requires restart)
wmic computersystem where name="%computername%" call joindomainorworkgroup name="WORKGROUP"

# View current workgroup/domain membership
systeminfo | findstr /B /C:"Domain"

# PowerShell method to join workgroup
Add-Computer -WorkgroupName "WORKGROUP" -Restart
Common Mistake: Computers in different workgroups can still communicate on the network, but they won't appear in the Network folder browsing list. The workgroup name is primarily for organization in Network Neighborhood - it's not a security boundary.
Speaker Notes: Joining a workgroup is straightforward and doesn't require any credentials or server contact. The workgroup name is just a label for network browsing organization. Unlike domains, there's no validation - you can type any workgroup name and Windows accepts it. The system must restart for the change to take effect. Remember that Windows Home edition can ONLY join workgroups, not domains.

Joining a Domain

How to Configure Domain Membership

Domain Join Requirements

Joining a domain requires Windows Pro or higher, network connectivity to a Domain Controller, and domain administrator credentials.

Steps to Join a Domain

  1. Verify Windows edition
    Must be Pro, Enterprise, or Education
  2. Configure DNS
    Point to Domain Controller's IP address
  3. Open System Properties
    Right-click This PC → Properties
  4. Click "Change settings" then "Change" button
  5. Select "Domain" radio button
  6. Enter domain name (e.g., "company.local")
  7. Provide domain admin credentials when prompted
  8. Welcome message appears if successful
  9. Restart computer to complete domain join

Prerequisites

Required:
  • Windows Pro, Enterprise, or Education (NOT Home)
  • Network connectivity to Domain Controller
  • DNS configured to point to DC
  • Domain administrator credentials
  • Unique computer name (no duplicates in domain)
Common Issues:
  • "Domain could not be contacted" - DNS misconfiguration
  • "Access denied" - Insufficient credentials
  • "Computer name already exists" - Name conflict in AD
  • Windows Home error - Edition doesn't support domain join
# Join domain via PowerShell (requires restart)
Add-Computer -DomainName "company.local" -Credential COMPANY\Administrator -Restart

# Join domain with specific OU
Add-Computer -DomainName "company.local" -OUPath "OU=Computers,OU=IT,DC=company,DC=local" -Restart

# Verify domain membership
systeminfo | findstr /B /C:"Domain"
Exam Tip: If a question states a computer cannot join a domain, check: 1) Windows edition (must be Pro+), 2) DNS configuration (must point to DC), 3) Network connectivity, 4) Valid admin credentials. These are the most common causes of domain join failures.
Speaker Notes: Domain joining requires proper DNS configuration - this is the most common failure point. The client must resolve the domain name to find Domain Controllers. During join, the computer account is created in Active Directory (in the default Computers container unless specified). Domain admins can also pre-create computer accounts in specific OUs. After joining, users can log in with "DOMAIN\username" or "username@domain.com" format.

Group Policy (Domain Feature)

Centralized Configuration Management

What is Group Policy?

Group Policy is a Windows feature that allows administrators to centrally manage and configure operating systems, applications, and user settings across the domain. It's one of the most powerful features exclusive to domain environments.

Group Policy Capabilities

  • Security Settings
    Password policies, account lockout, firewall, BitLocker, Windows Defender
  • Software Deployment
    Automatically install applications to users or computers
  • Desktop Configuration
    Wallpaper, screensaver, Start menu, taskbar customization
  • Restrictions
    Disable Control Panel, USB drives, registry editing, cmd.exe
  • Scripts
    Startup/shutdown (computer), logon/logoff (user) scripts
  • Folder Redirection
    Redirect Documents, Desktop to network location

Policy Application Scope

Computer Policies:
Applied to computer regardless of who logs in. Examples: Windows Update settings, startup scripts, computer security settings.
User Policies:
Applied to user regardless of which computer they use. Examples: desktop settings, mapped drives, application settings.

Policy Processing Order (LSDOU)

  1. Local - Computer's local policy
  2. Site - Active Directory site policies
  3. Domain - Domain-level policies
  4. OU - Organizational Unit policies (wins)
# Refresh Group Policy from client (force update)
gpupdate /force

# View applied Group Policies
gpresult /r

# Generate detailed HTML Group Policy report
gpresult /h C:\GPReport.html
Exam Tip: Group Policy is DOMAIN-ONLY. Workgroups cannot use centralized Group Policy (only local policies per computer). If a scenario requires enforcing settings across multiple computers from a central location, it requires a DOMAIN.
Speaker Notes: Group Policy is a game-changer for IT administration. Create a policy once, apply it to thousands of computers. Policies refresh every 90 minutes by default (plus random 0-30 minute offset). The LSDOU order means OU policies override domain policies, which override site policies, etc. "Last applied wins" unless policy is set to "Enforced" (then it cannot be overridden). Group Policy Objects (GPOs) are created and managed on Domain Controllers using GPMC (Group Policy Management Console).

When to Use a Workgroup

Appropriate Use Cases for Workgroup Networks

Workgroup Decision Criteria

Workgroups are appropriate for small, simple networks with minimal management requirements and limited budgets.

🏠 Home Networks

Personal home networks with family computers. No centralized management needed, simple file/printer sharing between rooms.

🏪 Small Office (<10 Computers)

Very small businesses with fewer than 10 computers. Minimal IT complexity, basic resource sharing, tight budget constraints.

👤 No IT Staff

Environments without dedicated IT personnel. Non-technical users can manage workgroups with basic training.

💰 Budget Constraints

Organizations that cannot afford Windows Server licensing and server hardware. Zero additional cost for workgroup functionality.

⚡ Temporary Networks

Ad-hoc or temporary networks for events, conferences, or short-term projects. Quick setup, no infrastructure required.

🧪 Testing/Lab Environments

Simple lab setups for learning or testing where centralized management isn't needed.

Example Scenarios:
  • Dental Practice: 1 front desk computer, 2 exam room computers, 1 office computer. Share patient scheduling software and printer. 4 total computers - workgroup is perfect.
  • Home Network: Parent's laptop, 2 kids' computers, media PC. Share photos and printer. Basic needs, no IT staff - workgroup works well.
  • Freelance Studio: 3 graphic designers sharing project files. Simple collaboration, minimal security needs - workgroup sufficient.
When Workgroups Become Problematic: Beyond 10-20 computers, administrative overhead increases dramatically. Managing 20 separate user accounts per user, inconsistent security policies, and lack of centralized control become major issues. At that point, domain investment becomes worthwhile.
Speaker Notes: Workgroups excel in simplicity and cost. The 20-computer guideline is practical, not technical. You could have 50 computers in a workgroup, but managing them would be a nightmare. For exam questions, if the scenario describes a small office (under 10-15 computers), no IT staff, limited budget, or home environment, workgroup is likely the answer. If it mentions growth plans, security requirements, or current size above 20 computers, recommend domain.

When to Use a Domain

Appropriate Use Cases for Domain Networks

Domain Decision Criteria

Domains are essential for business environments requiring centralized management, security, scalability, and single sign-on capabilities.

🏢 Business Environments

Any professional business environment with employees, shared resources, and productivity requirements. Standard for corporate IT infrastructure.

📊 10+ Computers

Networks with 10 or more computers benefit from centralized management. Domain overhead becomes worthwhile at this scale.

🎛️ Centralized Management Need

Organizations requiring uniform configuration, software deployment, and consistent security settings across all computers.

🛡️ Security/Compliance Requirements

Industries with regulatory compliance (HIPAA, PCI-DSS, SOX). Centralized security policies, audit logging, password enforcement required.

👨‍💼 IT Staff Available

Organizations with dedicated IT personnel who can manage Active Directory, Domain Controllers, and Group Policy infrastructure.

📈 Growth Plans

Small businesses planning to grow beyond 20 employees. Better to implement domain early than migrate later.

Example Scenarios:
  • Law Firm: 50 employees, strict confidentiality requirements, document management system, compliance regulations. Domain with Active Directory, Group Policy security, centralized file servers.
  • Medical Practice: 30 staff members, HIPAA compliance, electronic health records, multiple locations. Domain required for centralized authentication, audit logging, encrypted file access.
  • Manufacturing Company: 200 employees across office and factory floor. Need centralized user management, software deployment, roaming profiles so users can log in at any workstation.
Domain ROI (Return on Investment): While domains have upfront costs (server hardware, Windows Server licenses, IT expertise), they provide massive time savings in administration, improved security posture, and better user experience through single sign-on. For organizations with 20+ computers, domains typically pay for themselves within the first year.
Speaker Notes: Domains are the standard for business IT. The 10-computer threshold is when centralized management becomes cost-effective. For exam scenarios, if the organization has compliance requirements, needs centralized security, has IT staff, or is larger than 20 computers, recommend domain. Key indicators: "enforce security policies," "centralized management," "single sign-on," "compliance requirements" - these all point to domain.

Hybrid Scenarios: Azure AD & Cloud Identity

Modern Cloud-Based Domain Alternatives

Azure Active Directory (Azure AD / Microsoft Entra ID)

Azure AD (now called Microsoft Entra ID) is Microsoft's cloud-based identity and access management service. It provides domain-like capabilities without on-premises servers.

Azure AD Join

Connect Windows 10/11 Pro+ devices directly to Azure AD without traditional domain controllers.

Benefits:
  • No on-premises servers required
  • Cloud-based authentication
  • Single sign-on to Microsoft 365
  • Mobile Device Management (Intune)
  • Conditional Access policies
  • Multi-Factor Authentication (MFA)
Best For: Small businesses, remote workforces, cloud-first organizations, startups without on-premises infrastructure.

Hybrid Azure AD Join

Computers joined to both on-premises Active Directory AND Azure AD simultaneously.

Benefits:
  • Best of both worlds - on-prem + cloud
  • Access to on-premises file servers
  • Access to Microsoft 365 cloud services
  • SSO to both environments
  • Cloud backup for authentication
Best For: Enterprises transitioning to cloud, organizations with existing AD infrastructure, hybrid work environments.

Exam Tip: Azure AD is a KEY topic for modern A+ exams. Know that Azure AD Join requires Windows 10/11 Pro+ (like traditional domains). It's Microsoft's cloud alternative to on-premises Active Directory. Hybrid Join combines both for organizations transitioning to cloud.
Speaker Notes: Azure AD (Entra ID) is increasingly important as organizations move to cloud. It provides identity services without physical servers. Azure AD Join is similar to traditional domain join but authenticates against cloud. Hybrid Join is common during cloud migration - sync on-premises AD to Azure AD using Azure AD Connect tool. This provides authentication redundancy and enables cloud services while maintaining on-premises resources.

  • Simple file/printer sharing
  • ~20 computer maximum (practical limit)
  • Zero additional cost
  • All Windows editions supported
  • Best for: Home, small office, budget-limited

Domain Summary

  • Requires Domain Controller (Windows Server)
  • Domain accounts in Active Directory
  • Centralized management via Group Policy
  • Single sign-on capability
  • Scales to thousands of computers
  • Server licensing costs
  • Requires Pro/Enterprise/Education edition
  • Best for: Business, compliance, 10+ computers

Decision Factor: Size

<20 computers → Workgroup
10+ computers (business) → Domain

Decision Factor: Management

Individual PC management → Workgroup
Centralized control needed → Domain

Decision Factor: Budget

Limited/no IT budget → Workgroup
IT infrastructure investment → Domain

Decision Factor: Security

Basic security needs → Workgroup
Compliance/policies required → Domain

Final Thought: There's no "better" model - workgroups and domains serve different purposes. Choose based on organization size, management requirements, security needs, and available resources. Both have their place in IT infrastructure.
Speaker Notes: This summary reinforces the key decision factors. For the exam, remember that neither model is inherently superior - appropriateness depends on context. Small organizations benefit from workgroup simplicity; larger organizations require domain capabilities. The transition point is typically around 10-20 computers where administrative overhead of workgroups exceeds domain setup costs.
